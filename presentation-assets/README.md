# presentation-assets — 발표·데모용 증거 자료

실행 이력 DB(`data/`)는 `.gitignore` 대상이고 Cloud Run 의 SQLite 도 비영속이다. 그래서
**발표에 쓸 실 LLM 실행 결과는 이 폴더가 유일한 영속 사본**이다. 데모 당일 실행이 실패하거나
쿼터가 소진돼도 여기 있는 것으로 보여줄 수 있게 확보해 둔다.

## demo-results — 데모 백업 (실 LLM)

| 파일 | 내용 |
|---|---|
| `run-6.json` | 실행 State 전체(응답 그대로). 화면 재현·수치 확인의 원본 |
| `run-6-kosena.md` | KOSENA 7종 산출물 문서(과제 체크포인트 3의 결과물) |

"산출물"이라고 할 때는 `kosena` 쪽을 말한다.

### 표현 주의 (과장 금지)

- **`27/28` 은 이 실행(project_id=6)의 값이다.** 07-27 실행(project_id=3)은 `26/28` 이었다.
  **주제·실행이 다른 별개 측정이므로 두 값을 이어 붙여 "개선됐다"고 말하면 안 된다.**
  어느 쪽을 인용하든 실행 id·측정일·주제를 함께 말한다.
- **출처는 "실행 전체의 출처 존재 검사"** 다. "각 KOSENA 주장별 출처 검증"이라고 하면 틀린다
  (항목별 근거 연결은 미구현이며 문서 부록에도 그렇게 적혀 있다).
- **사실검증 범위는 검색 요약 기준**(`search_snippet_only`)이다. URL 원문은 재검증하지 않는다.
  `unsupported` 는 '거짓'이 아니라 '수집한 근거에서 확인하지 못함'이다.
- `retrieved_at` 19/19 는 **이 실행에서 실측된 값**이다. 07-27 실행에는 0/16 이었다
  (최신성 메타가 그 실행 이후 커밋에 들어왔기 때문) — 그 기록으로는 최신성을 보여줄 수 없다.
- 품질 게이트가 `release_ready=false` 인 것은 결함이 아니라 **게이트가 작동한 결과**다.
  다만 `fact_support_rate` 가 같은 문서 재판정에서 흔들리는 미해결 과제가 있다(문서화됨).
