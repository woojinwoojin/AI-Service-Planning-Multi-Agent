## 함께 읽어야 하는 한계 — 지우지 않았다

- **`release_ready=false` 다.** 품질 게이트를 통과하지 못했다. 게이트가 **작동한다**는 뜻이고,
  동시에 이 산출물이 **자동 출판** 기준에는 못 미친다는 뜻이다. 임계값은 `calibrated: false`
  (사람 기준선 보정 전 잠정값)이다. N=7 표본에서도 **0/7 통과**다.
- **본문 분량이 요건 미달**이다(약 13.6쪽 vs 30~50쪽). 분량을 위한 분량은 넣지 않았다.
- **사실 검증은 검색 스니펫 기준**이다. URL 원문의 사실성은 재검증하지 않으며,
  `unsupported` 는 '거짓'이 아니라 '수집한 근거에서 확인하지 못함'이다.
- **출처 검사는 실행 전체 기준**이다. KOSENA 산출물의 **항목별 근거 연결은 미구현**이다.
- **KOSENA 27/28 은 대표값이 아니다.** 서로 다른 7건에서는 **26~27/28(평균 26.4)** 이었다.
  이 샘플은 27/28 이 나온 실행이므로, 07 의 분포와 함께 읽어야 한다.
- 05·03 문서 말미의 **`검증 범위 및 한계`** 절과 부록의 판정 내역도 그대로 두었다.

## 알려진 표기 결함 (이 샘플에 실제로 남아 있다)

`부록 — 근거 출처` 표에서, 웹페이지 제목에 `|` 문자가 포함된 근거 2건(`ev12`·`ev9`)은 Markdown 표의
열이 밀린다. Markdown 원본에서는 열이 늘어나고, DOCX 에서는 헤더 개수를 넘는 칸이 잘려 제목이
`|` 앞까지만 보인다. 산출물 생성 시 제목의 `|` 를 이스케이프하지 않는 것이 원인이며, 코드 동결
이후 발견해 **고치지 않고 그대로 제출한다** — 실제 생성 결과를 손으로 편집하지 않는다는 원칙을
지키기 위해서다.

## 재현에 대해

LLM 출력은 실행마다 달라지므로 03~06 과 **바이트 단위로 같은 결과는 재현되지 않는다.** 그래서 그
실행의 State 를 `06` 으로 함께 제출한다. 실행 절차는 `09` 를, 표본 분포는 `07` 을 참고.
