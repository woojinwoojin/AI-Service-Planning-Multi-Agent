# 평가 기준 ↔ 구현 매핑표

> 과제 평가 기준(체크포인트)이 코드의 **어디로** 구현됐는지, 그리고 **무엇이 아직 아닌지**를
> 한 장에 모았다. 근거는 전부 파일·함수 단위로 지목한다.
> 갱신: 2026-07-27 · 테스트 658 passed · 실 LLM 실측 1주제(gpt-4o-mini)

**이 문서의 원칙**: 구현한 것과 앞으로 할 것을 섞지 않는다. `✅ 구현`·`🟡 부분`·`❌ 미구현`으로만
적고, 부분·미구현에는 **왜 그 상태인지**를 함께 쓴다. 과장은 평가에서 가장 비싸다.

## 알려진 한계 (구현하지 않기로 판단한 것 포함)

### 사실 검증의 범위

**검색 요약 근거와의 일치 여부만 판정한다. URL 원문의 사실성은 재검증하지 않는다.**
`verification_result.verification_scope == "search_snippet_only"` 로 코드가 이 사실을 들고 다니고,
화면·내보내기 문서·실행 JSON 이 같은 문구를 쓴다(`app/services/reliability.py` 단일 소스).

- `unsupported` 는 **'거짓'이 아니다** — 수집한 근거에서 확인하지 못했다는 뜻이다.
- 판정별 개수와 주장·근거 연결은 KOSENA 본문의 **부록**에 싣는다(`kosena_doc._verification`).
- ⚠️ **같은 문서를 반복 판정하면 `fact_support_rate` 가 0.2~0.9 로 벌어진다**(verify 가 주장을
  매번 새로 추출). `quality_gate` 가 이 값을 쓰므로 게이트 판정에 운이 섞인다 — 미해결 과제다.

### CD 를 부르는 정확한 이름 — '검증된 승인형 CD'까지

세 단계를 모두 지났으므로 이제 **"검증된 승인형 Cloud Run CD"** 라고 부를 수 있다.

| 단계 | 정확한 명칭 | 상태 |
|---|---|---|
| 워크플로 작성 | 수동 트리거형 Cloud Run 배포 워크플로 | ✅ |
| Required reviewers 설정 | 승인형 Cloud Run CD | ✅ 저장소가 PUBLIC 이라 무료 플랜에서 가능 |
| 실제 dispatch 성공 | **검증된** 승인형 Cloud Run CD | ✅ 2026-07-28 |
| main 자동 트리거 | + **자동 배포**(승인 게이트 유지) | ✅ 2026-07-28 |

**'자동'의 범위를 넘겨 말하지 않는다.** 트리거와 파이프라인 진행은 자동이지만 실서비스 반영
직전에 사람 승인이 남아 있다. 다음 두 표현은 **둘 다 틀린다**:

- "승인 없이 자동 배포된다" → 승인 게이트가 있다.
- "승인 없이는 배포가 불가능하다" → `can_admins_bypass=true` 라 관리자는 우회할 수 있다.
  1인 개발이라 `prevent_self_review=true` 로 두면 **아무도 승인할 수 없어 배포가 영구 정지**되므로
  자기 승인을 허용했다.

⚠️ 비공개 저장소는 요금제에 따라 Required reviewers 를 못 쓸 수 있다(이 저장소는 PUBLIC).

> **배포 성공 ≠ 실 모드.** 2026-07-28 첫 성공 dispatch 는 `dummy_mode` 가 켜진 채 돌아서, 모든
> 단계가 success 인데 공개 URL 이 더미로 덮였다(`/health` → `"dummy_mode":true`). 워크플로 결함이
> 아니라 **확인 방법**의 구멍이었다 — 이후 실행 모드를 Actions 요약과 `/health` 양쪽에서 보게 했다.

**인증은 WIF(Workload Identity Federation) 하나만 지원한다.** 서비스 계정 키(JSON) 폴백을 두지
않은 이유는 두 가지다 — 장기 크리덴셜을 저장소에 두면 유출 시 회수가 어렵고, 어느 쪽도 아직
돌려보지 못한 상태에서 갈래를 늘리면 실패 지점만 늘어난다. 수동 배포가 필요하면 이미 검증된
`scripts/deploy_cloudrun.sh` 가 있다.

> **처음 쓴 워크플로에는 실제 버그가 있었다**(외부 리뷰가 잡았다): 인증 단계를
> `if: ${{ secrets.X != '' }}` 로 갈랐는데, GitHub 의 컨텍스트 가용성 표에 `steps[*].if` 용
> 컨텍스트로 **`secrets` 가 없다.** 조건이 의도대로 평가되지 않아 **두 인증 단계가 모두
> 건너뛰어지고** 크레덴셜 없이 배포를 시도하게 된다. 시크릿을 조건으로 써야 한다면 job 의
> `env:` 로 옮겨 `env.X` 를 봐야 한다. 지금은 인증 방식을 하나로 고정해 조건 자체를 없앴다.

### 최신성 처리의 범위

**한 것**: 모든 근거에 조회 시점(`retrieved_at`) 기록 · 검색이 주는 경우 발행일(`published_date`) 기록 ·
경쟁사 동향 검색에 기간 조건(365일) · 수집된 근거를 출처 유형별로 분류해 정부·학술 우선 배치 ·
문서 부록에 검색 기준일 명시.

**측정 근거**(2026-07-27, 경쟁사 쿼리): 기간 조건이 없으면 일반 AI 문서(Wikipedia·강좌)가 올라오고,
`news/365d` 를 걸면 주제 적합 자료가 올라왔다. 경쟁사 쿼리는 고유명사가 적어 일반 검색이 상위어로
흘러가는데 뉴스 토픽이 그걸 막았다.

**안 한 것**: 발행일 기준 자동 노후 판정(N년 넘은 근거 자동 배제)은 하지 않는다 — 시장 통계·정책
원문은 오래돼도 1차 자료로서 유효하고, 기계적으로 자르면 오히려 권위 있는 근거를 버린다. 대신
발행일·조회일을 **문서에 그대로 노출**해 사람이 판단하게 한다. `published_date` 는 검색 제공자가
줄 때만 있어서 일반 검색 결과에는 대부분 '미상'으로 남는다.

### 출처는 '실행 전체' 기준이다

`sources_cited` 검사는 레지스트리에 URL 이 있는지만 본다. TAM/SAM/SOM·경쟁사 정보에 **직접
연결된 근거가 없어도 충족**이 된다. 14섹션 기획서 쪽은 `verify` 가 주장별 `evidence_ids` 를
붙이지만, **KOSENA 산출물의 항목별 근거 연결은 미구현**이다.
→ "각 KOSENA 주장별로 출처를 검증한다"고 말하면 **틀리다.**

### 본문 분량 (A4 30~50쪽 vs 약 12.2쪽)

**분량을 위한 분량은 넣지 않았다.** 같은 내용을 늘려 쓰거나 표를 쪼개 쪽수를 맞추는 것은
평가표의 '문서 완성도'(논리·시각화·인용)와 오히려 어긋난다. KOSENA 가 상정하는 30~50쪽은 팀이
**1차 자료(인터뷰·설문)와 부록·근거 자료를 붙인 분량**으로 보이며, 이는 자동 생성으로 메울
성질이 아니라 사람이 리서치 결과를 덧붙여 채우는 부분이다. 도구는 그 골격을 제공한다.

### 1차 자료를 만들 수 없다

평가표 '고객 이해' 우수 기준은 *인터뷰 + 설문*이다. AI 파이프라인은 이를 만들 수 없고, 지어내면
KOSENA 원칙(정량 주장은 1차 자료로 뒷받침)에 정면으로 위배된다. 따라서 목표를 '충족'이 아니라
**가설임을 명시하는 것**으로 두고, 그 표기 여부 자체를 검사한다(`hypothesis_labeling`).

### 이력 저장은 비영속이다

SQLite 파일(`data/projects.db`)에 저장한다. **Cloud Run 컨테이너는 재시작 시 파일이 사라지므로,
공개 배포에서 이력은 보존되지 않는다.** 사용자에게 산출물 다운로드를 안내하는 것으로 대응했다.
PostgreSQL 등 외부 DB 전환은 이번 제출 범위에서 제외했다(변경 위험 대비 이득이 작다).
⚠️ **GCS FUSE + SQLite 조합은 파일 잠금 문제로 금지**다(파일 손상).

### 프런트엔드에 CDN·빌드 도구를 쓰지 않았다

`app/static/index.html` 은 인라인 CSS/JS 단일 파일이다. 이유는 세 가지다:
FastAPI 가 그대로 서빙해 **빌드·CORS·별도 배포가 불필요**하고, 오프라인·폐쇄망에서도 동작하며,
외부 CDN 은 **가용성·버전 변동·공급망 위험**을 끌어들인다. 백엔드가 이 프로젝트의 주인공이라
프런트엔드 복잡도를 의도적으로 낮게 유지했다.
⚠️ 대가: **JS 자동 테스트가 없다**(이 환경에 node 도 없다). UI 변경은 브라우저 수동 확인에
의존하며, 실제로 테스트 전부 통과 상태에서 화면이 깨진 적이 있다.
