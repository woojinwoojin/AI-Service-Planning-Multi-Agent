# 08 향후 발전 방향 및 소회 — 슬라이드 문안 (2p · 50초)

이 섹션의 목적은 두 개다. ① **Q&A 의 공격 카드를 미리 없애는 것** ② 관통 문장으로 01~07 을
하나로 묶는 것. 한계를 먼저 말하면 *숨긴 결함*이 아니라 **검증을 통해 확인한 개선 과제**가 된다.

**시간을 깎지 않는다.** 여기서 5초 아끼고 Q&A 에서 2분을 잃는 교환이 된다.

---

## p1 — 알려진 한계와 로드맵 (25초)

### 제목
**"지금 안 되는 것을 먼저 말합니다"**

제목을 이렇게 잡는 이유: 심사자가 다음 25초를 *변명*이 아니라 *자기 평가*로 듣게 만든다.

### 슬라이드 상단 — 반드시 말할 3개 (굵게)

| 한계 | 한 줄 |
|---|---|
| **품질 게이트 0/7 통과** | 게이트가 **작동한다**는 뜻이고, 동시에 **자동 출판 기준에는 못 미친다**는 뜻. 임계값은 `calibrated: False` — 사람 기준선 보정 전 잠정값 |
| **근거 확인율 0.20 ~ 1.00** | 검증 Agent 가 주장을 매번 새로 추출해 판정에 **운이 섞인다.** 분모가 5건 내외라 한 주장에 0.2 씩 움직인다. **미해결** |
| **고정 그래프 — 자율 아님** | **"자율 multi-agent" 라고 말하지 않는다.** 동적 위임은 `research_gap`(근거 공백에만, 상한 2)까지 |

### 슬라이드 하단 — 나머지 한계 (작게, 읽지 않고 넘김)

| 한계 | 요지 |
|---|---|
| 문서 분량 | KOSENA 권장 30~50쪽 vs 약 11~13쪽. **분량을 위한 분량은 넣지 않기로 판단** |
| 항목별 근거 연결 미구현 | 코드가 "이게 TAM 근거겠지"를 추론해 부록을 만들면 그것도 허위다 |
| 사실검증 범위 | `search_snippet_only` — 검색 요약 기준, URL 원문 미검증 |
| 이력 비영속·무인증 | Cloud Run SQLite 는 재시작 시 소멸 · `/projects` 무인증 → 입력 화면에 고지 |
| Artifact Contract | 스키마·호환성 검증은 완료했으나, 제출 버전은 **안정성을 위해 기존 State 읽기 경로를 유지**(`ARTIFACT_READ_MODE=legacy`) |
| UI 자동 테스트 없음 | node 미설치 → 화면은 사람이 확인해야 한다 |
| 완전 무인 배포 아님 | 승인 게이트를 **일부러** 남겼다(실 키 붙은 공개 서비스) · `enforce_admins=false` |

### 로드맵 (오른쪽 열)

| 우선순위 | 항목 |
|---|---|
| 1 | **사람 기준선 보정** — 게이트 임계값을 인간 평가와 맞춘다(0/7 의 원인을 먼저 규명) |
| 2 | **근거 확인율 안정화** — 주장 추출을 고정해 판정에서 운을 제거 |
| 3 | **항목별 Evidence 연결** — KOSENA 항목 ↔ 근거를 명시적으로 잇는다 |
| 4 | URL 원문 검증(Tier 3) · Cloud SQL 전환 · 정적 리소스 CDN 분리 |

**순서에 근거가 있다** — 1·2 는 이미 실측으로 문제가 확인된 것이고, 3·4 는 기능 확장이다.
"측정된 문제부터 고친다"는 순서 자체가 답변이 된다.

### 나레이션 (약 150자)
> "한계를 먼저 말씀드립니다. **품질 게이트는 7건 모두 통과하지 못했습니다** — 게이트가 작동한다는
> 뜻이고, 동시에 자동 출판 기준에는 못 미친다는 뜻입니다. 임계값 자체가 사람 기준선 보정 전
> 잠정값입니다. **근거 확인율은 0.2에서 1.0까지 흔들립니다** — 판정에 운이 섞이고, 미해결
> 과제입니다. 그리고 **그래프는 고정입니다 — 자율 multi-agent 라고 말하지 않겠습니다.**"

## p2 — 소회 및 결론 (25초)

### 제목
**"근거와 검증 과정을 추적할 수 있는 기획 초안 생성 시스템"**

⚠️ **"초안"을 반드시 유지한다.** 품질 게이트 0/7 과 일관된 유일한 표현이다. "완성된 기획서"라고
쓰면 그 자리에서 무너진다.

### 슬라이드 중앙 — 관통 문장 재등장

> ## **"확인되지 않은 내용을 임의로 채우지 않고, 실패와 불확실성을 결과에 그대로 반영합니다."**

표지에 썼던 문장을 **글자 그대로** 다시 띄운다. 처음과 끝이 같은 문장이면 기억에 남는다.

### 아래에 사례 4개 (문장 하나가 어떻게 코드로 구현됐는지)

| 사례 | 실측 |
|---|---|
| 직접 경쟁사가 2개면 3개를 만들지 않는다 | 준수율 26~27/28 로 **흔들리는 것을 그대로 뒀다** (7건 중 4건) |
| 재작성본이 낮게 평가되면 초안으로 되돌린다 | 7건 중 **2건(29%)** 에서 실제로 되돌렸다 |
| 기준 미달이면 `release_ready=false` | **0/7 통과** — 통과시키려고 기준을 낮추지 않았다 |
| 실패를 성공으로 덮지 않는다 | `degraded` 유지 + `fallback_reasons`. **이 표기를 지우던 결함 2건을 찾아 고쳤다**(#130·#132) |

**코드 레벨 근거 한 줄**: `app/prompts/templates.py:23-29` 의 `NO_FABRICATION_RULE` 이 모든
페르소나 프롬프트에 문자열로 합성된다 — 선언이 아니라 프롬프트에 들어가 있다.

### 나레이션 (약 155자)
> "결론은 표지에 썼던 문장 그대로입니다 — **확인되지 않은 내용을 임의로 채우지 않고, 실패와
> 불확실성을 결과에 그대로 반영합니다.** 경쟁사 개수를 채우지 않아 준수율이 26과 27을 오가고,
> 재작성본이 나쁘면 초안으로 되돌리고, 기준에 못 미치면 통과시키지 않습니다. 그리고 **실패
> 표기를 지우던 결함을 두 번 찾아 고쳤습니다.** 이 시스템이 내놓는 것은 완성된 기획서가 아니라
> **근거를 추적할 수 있는 초안**입니다."

### 소회 (시간이 남으면 한 문장, 슬라이드에는 넣지 않음)
> "만들면서 가장 많이 배운 건 **측정하지 않으면 만든 사람도 속는다**는 것이었습니다. 발표 전날
> 찾은 결함도 화면 숫자와 측정 숫자가 다른 걸 의심한 데서 나왔습니다."

## Q&A 대비 — 이 섹션에서 유도되는 질문

| 질문 | 답변 |
|---|---|
| **"게이트를 통과 못 하면 실용성이 없는 거 아닌가요?"** | 게이트는 **자동 출판** 기준입니다. 사람이 검토·보완하는 초안으로는 쓸 수 있고, 무엇이 부족한지를 점수·major 이슈·근거 충족률로 **항목화해** 줍니다. 임계값이 보정 전 잠정값이라 "80점 미달 = 품질 낮음"으로 읽는 건 맞지 않습니다 |
| **"자율이 아니면 multi-agent 라고 할 수 있나요?"** | 복수 Agent 분업·의존 관계·병렬 실행·조건부 분기·실패 격리는 모두 구현돼 있고 테스트로 고정돼 있습니다. 없는 것은 **Agent 가 다음 할 일을 스스로 계획하는 것**이고, 그건 명시적으로 한계로 적었습니다 |
| **"확인율이 흔들리는데 검증이 의미가 있나요?"** | 흔들리는 것은 **확인율 수치**이고, `retrieved_at` 전건 기록·출처 목록·주장별 판정 자체는 결정적으로 남습니다. 사람이 재검증할 **출발점**을 제공하는 것이 현재 범위입니다 |
| **"분량이 권장의 1/3인데 KOSENA 준수라고 할 수 있나요?"** | 28개 항목 중 분량 하나가 부분 충족입니다. **분량을 채우려면 근거 없는 문장을 넣어야 해서** 넣지 않기로 판단했고, 그 판단을 미충족으로 그대로 보고했습니다 |
| **"앞으로 뭘 먼저 하실 건가요?"** | **측정으로 확인된 문제부터**입니다 — 게이트 임계값의 사람 기준선 보정, 그리고 근거 확인율 안정화입니다. 기능 확장(URL 원문 검증·CDN 분리)은 그다음입니다 |
