# KOSENA 방법론 준수 현황 (체크포인트 3)

> 근거: `KOSENA_AI_서비스기획.pdf`(21쪽). 쪽수는 원문 대조용으로 각 항목에 표기했다.
> 판정은 코드가 한다 — `app/services/kosena.py:evaluate`, 실행마다 `state["kosena_compliance"]`.
> 갱신: 2026-07-27

## 왜 이 문서가 있는가

과제 체크포인트 3은 **"제공된 기획 방법론 템플릿(KOSENA)을 준수하는가"** 다. KOSENA 는 문서
디자인 템플릿이 아니라 **반드시 거쳐야 하는 분석 프레임워크와 산출물 구조**를 규정하고,
평가표(p20)도 프레임워크 정확도·Lean Canvas 일관성·TAM/SAM/SOM 교차검증·VPC Fit·
MVP/Epic-Story-AC/와이어프레임을 **직접** 본다.

점검 결과 **현재 파이프라인은 체크포인트 1·2 는 충족하지만 체크포인트 3 은 부분 충족**이다.
이 문서는 그 격차를 **숨기지 않고 항목 단위로 고정**한다. 평가에서 '표면적 적용'보다 나쁜 것은
'무엇이 빠졌는지 모르는 상태'다.

## 구조적으로 채울 수 없는 항목 (정직 표기)

평가표(p20) **'고객 이해'** 우수 기준은 *1차 인터뷰 + 설문 + 정성 통찰*이고, 페르소나 정의도
*인터뷰 5명 + 설문 100명*을 예로 든다(p12). **AI 파이프라인은 이를 만들 수 없다.**

지어내면 KOSENA 원칙(*정량 주장은 1차 자료로 뒷받침*, p4)에 정면으로 위배된다. 따라서 목표는
'충족'이 아니라 **가설임을 명시하는 것**이고, 검사도 그 표기 여부를 본다
(`hypothesis_labeling`). 예:

> 본 페르소나는 웹 리서치에 기반한 **가설형 페르소나**이며 실제 인터뷰로 검증되지 않았습니다.
> SOM 은 1~3년차 점유율 **가정**을 사용한 추정치이며 실제 점유율이 아닙니다.

이 태도는 PDF 의 결론과도 맞는다 — *"완벽한 기획서가 아니라 의사결정 가능한 가설을 만든다"*(p21).

## 보완 방향

**새 Agent 10개를 만드는 문제가 아니다.** 다만 *"기존 산출물을 재조립하면 된다"* 도 정확하지
않다 — 위 표에서 보듯 **재료 자체가 없는 항목이 다수**다(Porter·Lean Canvas 6블록·CJM·
TAM/SAM/SOM·VPC·MOSCOW·Kano·Epic-Story). 이들은 포맷팅이 아니라 **새 분석**이 필요하다.

| 구분 | 항목 |
|---|---|
| 재조립으로 가능 | 경쟁사 3·2·1 분류, 포지셔닝 맵(기존 비교표 + 축), 핵심 기능 개수 규격 |
| **새 LLM 분석 필요** | Porter, Value Chain, KSF, 시사점, HMW, Lean Canvas, 페르소나 2종, CJM, TAM/SAM/SOM, VPC, Use Case, MOSCOW, Kano, MVP, Epic-Story-AC, 와이어프레임 |
| 형식만 맞추면 됨 | AI 활용 로그(Artifact 메타데이터 재사용) |

**유리한 점**: PDF p7 의 프레임워크 체인 —
> 거시환경(PESTEL) → 산업환경(Porter) → 자사환경(SWOT) → KSF 도출

이 구조가 이 프로젝트의 **Artifact `depends_on` 모델과 그대로 대응**한다. 새 Agent 를 그 위에
얹으면 의존 관계가 자동 기록되고, 기존 검증(`depends_on` ↔ 런타임 읽기 대조)이 그대로 적용된다.

**내보내기는 추가 작업이 거의 없다.** `docx_export`·`pptx_export` 가 **markdown 을 입력으로**
받고 표를 렌더링하므로(`add_table`, 넘침 시 자동 분할), KOSENA 구조를 markdown 으로 만들면
DOCX/PPTX 는 따라온다.

## 이 검사를 쓰는 법

```bash
python run_kosena_check.py            # 더미 1회 실행 → 현황 리포트(무비용)
python run_kosena_check.py --real     # 실 LLM 1회(비용 발생) — 출처 항목까지 실측
```

실행 결과에는 `state["kosena_compliance"]` 로 항상 포함되고, 저장·재조회에도 남는다
(`_RUN_KEYS`). 옛 기록은 재조회 시 소급 판정된다.
