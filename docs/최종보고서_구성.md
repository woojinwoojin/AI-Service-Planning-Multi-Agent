## 0. 보고서 전체를 관통하는 메시지 (3개)

1. **Multi-Agent 의 가치는 '점수'가 아니라 '추적 가능한 근거'다.**
   단일 프롬프트는 출처 URL **0건**, 이 파이프라인은 **5건**을 인용한다(6주제 실측). LLM 심판
   점수 차이는 84.9 → 86.5 로 작지만, 출처 유무는 모델을 바꿔도 뒤집히지 않는 **구조적 차이**다.
2. **검증의 범위와 한계를 코드가 들고 다닌다.**
   `verification_scope=search_snippet_only` · `retrieved_at` 전건 기록 · `release_ready` 게이트 ·
   `data_source: real|dummy`. 못 한 것을 못 했다고 **산출물 자체가** 말한다.
3. **모자란 것을 지어내 채우지 않는다.**
   경쟁사 3개를 못 채우면 부분 충족으로 보고한다(그래서 준수율이 26~27 로 흔들린다). 재작성본이
   초안보다 나쁘면 되돌린다(7건 중 2건). 분량을 위한 분량은 넣지 않는다.

> ⚠️ 이 세 문장은 **"자율 multi-agent"라고 말하지 않는다**는 제약과 함께 써야 한다. 그래프는
> 고정이고, 동적 위임은 근거 공백 보강(상한 2)까지다.

## 3. 6장에 반드시 넣을 '사건 하나' — 결함을 어떻게 잡았나

보고서의 신뢰도를 가장 크게 올리는 절이다. `docs/동결_기록.md` '원인 규명'.

- **증상**: UI 로 실행하면 KOSENA 가 **11~12/28**, 스크립트로 측정하면 **26~27/28**
- **오진 1**: "Tavily 쿼터 문제" → 검색을 완전히 차단해 재측정하니 **26/28 · Agent 4/4 완주**
  (검색 실패는 방법론 산출물 붕괴로 번지지 않는다는 **역설적 실증**)
- **오진 2**: "배포 환경 고유 문제" → 로컬 UI 에서도 재현
- **진짜 원인**: `apply_node_update()` 가 그래프 **밖**에서 상태를 합칠 때 reducer 필드를 손으로
  나열했고 그 목록에 **`kosena` 가 빠져** `dict.update` 가 앞선 3개 Agent 의 18개 키를 덮었다.
  `/run`(reducer 적용)은 정상, `/run/stream`(UI)만 깨졌다 — **환경 차이가 아니라 코드 경로 차이**
- **왜 테스트 667개를 통과했나**: **두 경로를 대조하는 테스트가 없었다**
- **수정·검증**: 2행 + 기존 reducer 재사용 · 회귀 테스트 8개(되돌리면 5개 실패) · 실 LLM
  `/run/stream` 관통 **28키 · 27/28 · 미충족 0**

교훈으로 쓸 문장: **"`run_status: success` 는 결과가 보존됐다는 뜻이 아니다"**, **"드물게
발생한다는 서술은 원인을 모른다는 뜻이다"**.

### ⚠️ 분량(`doc_length`)은 두 숫자를 같이 써야 한다

| 기준 | 값 |
|---|---|
| 자체 점검(`kosena._c_doc_length`) | **약 13.6쪽** — `문서 줄 수 ÷ 45줄` 기반 **추정** |

실제 Word 렌더링은 26쪽이다. 어느 기준이든 요건 30~50쪽에는 미달이며, 분량을 위한 분량은 넣지
않기로 판단했다"* 로 쓴다. 미달이라는 결론은 바뀌지 않지만 **격차는 4쪽 수준**이다.

사람 기획서 기준선 보정(게이트 임계값 교정) · 사용자 인증·이력 소유권 · per-Agent 관측 분해 ·
`Artifact` 읽기 경로 전면 전환.

## 7. 숫자를 말할 때 지킬 것 (그대로 옮김)

### ❌ 쓰면 안 되는 표현

| 하지 말 것 | 왜 |
|---|---|
| "KOSENA 27/28 을 달성했습니다" | 7건 중 3건만 27. 표본은 **26~27** 을 지지한다 |
| "26/28 에서 27/28 로 개선했습니다" | 개선이 아니라 경쟁사 개수 편차다. 코드는 동일 |
| "28개 항목을 모두 충족했습니다" | `doc_length` 는 7/7 미달 |
| "품질 게이트를 통과합니다" | **0/7 통과.** 게이트는 막는 쪽으로 작동했다 |
| "각 KOSENA 주장마다 출처를 검증했습니다" | 출처 검사는 실행 전체 존재검사. 항목별 연결 미구현 |
| "모든 Agent 가 Artifact Contract 로 통신합니다" | 동결은 `legacy` 읽기 모드다 |
| "자율 multi-agent 입니다" | 그래프가 고정이다 |
| "실행당 $0.022 입니다"(단정) | 범위 $0.016~0.024 |
| "근거 확인율 0.49"(단독) | 분모가 5건뿐. 범위 0.20~1.00 과 함께 |
| "이 결함은 드물게 발생합니다" | **결정적**이었다. UI 경로는 매번 깨졌다 |

### ✅ 인용 규칙

- 측정치는 **실행 id · 측정일 · 주제 · 모델**을 함께 적는다.
- 표본 크기를 반드시 적는다(N=7 · 6주제 · 3주제 · 10건 · 18회).
- 추정치(비용·쪽수)와 실측치(호출 수·토큰·시간)를 구분해 적는다.
- `26~27/28` 처럼 **범위로** 적고, 평균은 괄호에 둔다.
